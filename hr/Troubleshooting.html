Troubleshooting

Common problems in Dynamics 365 HR and how to resolve them. Use the contents list on the right to jump to a section, or press Ctrl+F to search this page.

Navigating D365 HR​

I can't sign in to D365 HR​

Cause — A personal or non-GEMS Microsoft account is being used, or the portal link is wrong.

Fix — Sign in with your GEMS Microsoft 365 email address. The portal URL is provided by your system administrator. Where single sign-on is in use and you are already signed into Microsoft on the device, you are signed in automatically.

The Human Resources module isn't in the module list​

Cause — Module visibility depends on the security roles attached to your account.

Fix — Use the search bar at the top of the screen to search for the form by name. If it still doesn't appear, contact your system administrator to confirm your role.

The navigation pane has disappeared​

Cause — The pane has been collapsed.

Fix — Click the hamburger menu (☰) at the top-left of the screen to expand it again. The Home icon in the pane returns you to your home page at any time.

My changes aren't saving​

Cause — The record is not in edit mode. Most D365 forms open read-only.

Fix — Click Edit in the Action Pane, make your changes, then click Save. The Back, Save/Edit, and New buttons stay anchored at the top of the record as you move between tabs.

Questionnaires​

The questionnaire I want isn't in the Questionnaire field​

Cause — A questionnaire must already exist in the system before it can be scheduled.

Fix — Create the questionnaire first, then return to Questionnaire ▸ Distribute ▸ Questionnaire schedules and select it.

Employees can't see the questionnaire in ESS​

Cause — The schedule hasn't been started, the current date sits outside the schedule window, or the recipients weren't set.

Fix — Open the schedule and check three things: that Setup details names the right people, teams or business segments; that today's date falls between the Start date and End date; and that Start has been clicked to activate the schedule.

The questionnaire went to the wrong schools​

Cause — Recipients are chosen in Setup details by person, team or business segment. Schedules are normally created in the GCO entity and can be released to one school or across all companies.

Fix — Reopen Setup details on the schedule and correct the selected teams or business segments.

An employee isn't showing on the intentions inquiry​

Cause — The Employee Intention Survey Result form only lists employees who answered Yes to the intention-to-leave question.

Fix — Check whether the employee has submitted the Intention Questionnaire at all. Responses appear live as employees submit through ESS.

I can't edit the fields on an intentions record​

Cause — Most fields on the Employee Intention Survey Result form are read-only by design.

Fix — Click Edit in the Action Pane. Only Retention Status and Comments can be changed.

The offboarding exit survey hasn't been issued​

Cause — The exit survey is generated by a batch job that only picks up employees who have been assigned an offboarding checklist.

Fix — Confirm the employee has an active offboarding checklist, then run Questionnaire ▸ Periodic Question ▸ Questionnaire Schedule for Offboarding Employee. The batch can also be scheduled to run nightly.

I can't find an employee's questionnaire answers​

Cause — Answers are held separately from the schedule record.

Fix — Go to Questionnaire ▸ View and analyse results ▸ Answers by person, filter to the employee, then click Answers in the Action Pane. Use the questionnaire number as your reference.

Onboarding​

No onboarding checklist was applied when the hire completed​

Cause — Either no default checklist is nominated in HR parameters, or the action type used for the hire doesn't have the checklist flag enabled.

Fix — Check both: Human Resources parameters ▸ Recruitment must name an Onboarding checklist, and the relevant entry in Personal action types must have Apply onboarding checklist enabled.

Only one member of the group received the task​

Cause — Checklist tasks route to the group's primary member, not to everyone in the group.

Fix — This is expected. To change who receives tasks, right-click the group, choose View Details, select the correct member, and click Make Primary.

The task went to someone outside the group​

Cause — The primary group member has an active delegation configured.

Fix — Delegated tasks route automatically to the delegate. Check the primary member's delegation settings if this wasn't intended.

An employee can't complete a task in ESS​

Cause — The task has a dependency on another task that hasn't been finished.

Fix — The task detail view in ESS shows which tasks are blocking progress and who is responsible for them. The task unlocks once all dependencies are complete.

A task is appearing for the wrong school​

Cause — The task's Company field is either set to the wrong legal entity or left blank. Tasks with no company set apply to all schools.

Fix — Open the task in the checklist and set Company to the specific legal entities the task should apply to.

I can't see the employees I want when building a user group​

Cause — User groups are scoped by legal entity. Employees at other schools aren't visible in the current context.

Fix — Switch legal entity context to the relevant school, or use the position, job title and name filters to narrow the visible list.

The task due dates are wrong​

Cause — Onboarding and pre-onboarding checklists calculate dates differently.

Fix — Onboarding tasks use due date offset from start date — days after the employee starts. Pre-onboarding tasks use an offset date — days before the target date set when the checklist is applied. Check which type of checklist you're editing.

Only pre-onboarding checklists are available on the worker action​

Cause — The Process type in the checklist assignment dialog is set to Pre-onboarding.

Fix — This is expected — only checklists matching the selected process type are listed. The onboarding checklist is applied automatically once the worker action is fully approved and completed.

Visa and Work Authorisation​

A visa type or profession is missing from the dropdown​

Cause — Dropdown values come from the Visa master setup tables, which were pre-loaded during migration.

Fix — Add the missing value under Human Resources ▸ Setup ▸ Visa master — Visa Type, MOL Profession, MOE Profession, or Contract Type as appropriate — then click Save.

I can't tell the profession codes apart in a dropdown​

Cause — Codes on their own are ambiguous.

Fix — Descriptions are displayed alongside codes in every dropdown selection. If a description is missing, add it to the profession record in the Visa master setup.

No expiry alerts are appearing for an employee's documents​

Cause — Alerts are driven by the saved expiry date and the threshold configured for that document type.

Fix — Confirm the expiry date is recorded on the visa or identification record. Thresholds — how far ahead the alert triggers — are configured per document type in system setup, so a passport alert may start 50 days out while another type starts closer to expiry.

The Expiring Records tile is empty​

Cause — No documents currently fall within the configured expiry threshold.

Fix — No action needed. Open Human Resources ▸ Workspaces ▸ Personnel management to see the tiles for each document type.

The ABC Category field won't let me change it​

Cause — ABC Category is derived from the visa type.

Fix — Change the Visa Type on the worker action and the ABC Category updates automatically.

The applicant's passport details didn't carry over to the new employee​

Cause — Identification records carry over to the Pending Worker Visa Information form, but only publish to the employee record when the worker action is completed.

Fix — Open Pending Worker Visa Information, find the worker, and click View Documents to confirm the records are present. Then complete the worker action through the standard workflow. Afterwards, verify in Employee Visa Information and in the employee's Person Identifications.

A worker isn't listed on the Pending Worker Visa Information form​

Cause — The form only holds pending worker actions that are not yet complete.

Fix — If the worker action has already been completed, look at the employee record instead. If the hire hasn't been initiated, start the worker action first.

HR Requests​

A request type isn't showing in ESS​

Cause — The WebESS display toggle is switched off for that request type.

Fix — Open the request type in Human resources ▸ Setup ▸ HR request types and switch WebESS display on. Request types that HR initiates internally are deliberately hidden from ESS.

Request types are in the wrong order in ESS​

Cause — The list is ordered by the ESS display order value.

Fix — Set a lower number to move a request type towards the top of the list, and a high number to push it to the bottom.

Employees are submitting requests without the information we need​

Cause — The field is set to Visible but not Mandatory.

Fix — Open Header setup on the request type and switch the Mandatory toggle on for that field. Employees then can't submit until it's completed.

The Attachment option isn't in the field list​

Cause — Attachments are available on every request type by default, so the option isn't listed as a configurable field.

Fix — No action needed. Employees can always attach a file to any request.

A submitted request isn't going to anyone for approval​

Cause — No approval workflow has been assigned to the request type.

Fix — Open the request type, select the appropriate Workflow from the dropdown, and save.

New submissions aren't appearing on the HR Request form​

Cause — The list holds its loaded state.

Fix — Click Refresh on the HR Request form to pull in new submissions. Each has a system-generated request number.

The status still shows as pending in ESS after I completed the request​

Cause — The ESS cache refreshes on a five-minute cycle.

Fix — Allow 3–5 minutes for the updated status to appear. This delay is by design.

The employee says they can't see our response​

Cause — The response was recorded somewhere other than the field ESS surfaces.

Fix — Enter your response in the HR notes field. That text is what the employee sees on their completed request. Any file you add with Attach is downloadable by the employee from the same place.

Probation​

No probation review was generated for an employee​

Cause — One of several things stops the batch creating a review: the review date falls outside the horizon, the date has already passed, the employee is excluded, or the batch hasn't run.

Fix — Check in order — that Exclude from Probation is set to No on the employee record; that the Stage 1 or Stage 2 date falls within the Probation Horizon Days value; and that Generate probation review has run under System Administration ▸ Periodic tasks ▸ Batch. Reviews are not generated retrospectively for dates that have already passed.

The probation dates or template are wrong for an employee​

Cause — Probation parameters are set per combination of Staff Level and Default category, and the employee's combination may be configured differently — or may not match the one you expect.

Fix — Check the employee's staff level and category, then review that row's Stage 1 and Stage 2 review days and template in the probation configuration form.

The manager can't find the review​

Cause — Reviews are routed into the manager's queue by the batch, not created directly on the employee record.

Fix — The review appears in the manager's ESS queue under Team Probation Review Requests once the batch has run and the Review 1 Generated or Final Review Generated flag is set to Yes.

An employee has passed probation but their status still isn't Confirmed​

Cause — Probation status is not updated automatically.

Fix — After a Stage 2 review completes with a Meets Expectations outcome, HR is notified. Open the employee record, go to Work history, and set Probation Status to Confirmed.

The employee wasn't told their Stage 2 outcome​

Cause — Where the outcome is Performance Concerns, the workflow routes to HR only.

Fix — This is by design — the employee is not notified. HR takes the appropriate next steps directly.

I need to see who actioned each step of a review​

Cause — The review record shows the current status, not the full routing history.

Fix — Open the review in HR Probation Reviews and click View History to trace each action, which workflow conditions evaluated true or false, and when each step completed.

Identification​

The Submit button is disabled in ESS when adding an identification document​

Cause — An attachment is mandatory for that document type at that company, and no file has been uploaded.

Fix — Upload the supporting file and the Submit button becomes available. To change the rule, update Attachment mandatory for company on the identification type.

Different document types are asking for different fields​

Cause — Mandatory fields are configured separately for each identification type.

Fix — This is expected. A passport asks for issue date, end date and place of issue; Khamra asks for an agency rather than a country; medical insurance requires no issuing agency.

An identification rule is applying to the wrong staff​

Cause — Rules are scoped by legal entity (company) and by Worker region.

Fix — Open the identification type and check both scoping settings so the requirement only applies to the intended schools or locations.

Benefits​

A component isn't showing on the employee rewards statement​

Cause — Components with no Reward Type set are excluded from the statement.

Fix — Open the component in Human Resources ▸ Setup ▸ Compensation ▸ Component master, click Edit, set a Reward Type, and save.

A component is showing in the wrong category​

Cause — The Reward Type value determines which category the component appears under.

Fix — Change the Reward Type to the correct option — Fixed Allowance, Living, or Other — and save.

I can't tell which components have already been configured​

Cause — The component master lists every component regardless of configuration.

Fix — Filter the Reward Type column to where the value is not empty. That shows everything currently included in the rewards statement; clear the filter to find components still to be configured.

Offboarding​

I can't assign an offboarding checklist​

Cause — The checklist must exist and have a primary task owner before it can be assigned.

Fix — Go to Human Resources ▸ Task Management ▸ Offboarding checklists, select or create the checklist, assign the monitoring group under Assigned to, select a user and click Make Primary, then save.

The offboarding checklist isn't available on the employee's action​

Cause — The Process type in the Apply checklist dialog is set to something other than Offboarding.

Fix — In Actions ▸ Checklists ▸ Apply checklist, set Process type to Offboarding, choose the checklist, and click OK.

The offboarding task due dates look wrong​

Cause — Task dates are calculated from the target date set when the checklist is applied.

Fix — Set the Target date to match the termination end date entered on the personnel action. Individual task dates are then derived from each task's offset.
